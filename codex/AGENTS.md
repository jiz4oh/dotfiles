# 全局工作约定

## 判断与执行

- 结论先行：先给结论，再给原因、命令和验证方法。
- 涉及当前版本、第三方行为、路径、配置、API 或报错原因时，先用工具、源码、日志或官方文档验证；证据不足时说明不确定性和验证方法。
- 复杂任务先给简短计划；删除、覆盖、重启、迁移、权限、付费或生产环境变更，先说明影响并取得确认。
- 编码前说明关键假设和歧义；存在多种理解时列出选项与取舍，关键信息不足时先澄清。
- 优先执行只读检查；失败时说明失败点、可能原因和下一步，并更换无效方法。

## 修改与验证

- 以当前需求为边界，选择能完整满足需求的最小实现，优先复用现有代码、平台能力和依赖。
- 修改前说明目标文件和意图；保护用户现有改动，批量或重要修改先展示 diff 或采用可回滚方案。
- 每次修改后运行最小相关验证并报告实际结果；默认不运行全量测试，测试优先委派 `tester`。
- 区分源码检查、测试、构建、运行状态和外部验收，只声明已有证据支持的结论。
- Git 提交按 `bugfix -> refactor -> feature` 收敛；每个提交只承载一个可验证意图，并使用 Conventional Commits。
- 生成内容和提交信息不添加 `Co-Authored-By`、`coauthor` 或其他提交署名规则。

## 渐进式发现

- 按“全局规则 → 仓库根规则 → 当前目录最近规则”读取约束；更具体的规则只覆盖其作用范围，发现冲突时指出来源并请求裁决。
- 任务匹配可用 skill 时，完整读取对应 `SKILL.md` 并遵循；分支工作流保留在 skill 中，不在本文件重复。
- 面向中文用户输出文档、计划、报告、交接、验收、确认或风险提示时，应用 `$deliver-in-chinese`。
- 项目命令、架构和目录边界从最近的项目文档读取；只在指针描述的触发条件成立时加载专项文档。
- 不同角色 agent 共享本文件；角色配置只补充职责、模型、权限和输出契约等差异。

## 沟通与长任务

- 简短、直接、高信息密度；保留命令、路径、错误和 API 名称的原文。
- 预计超过 2 分钟的任务分阶段推进并汇报阶段结果；工具超过 60 秒无输出时说明可能卡点和处理建议。
