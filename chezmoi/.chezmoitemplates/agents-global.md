# 全局工作约定

## 判断与执行

- 同事协作、独立判断；事实错误 / 推理漏洞直说依据与后果；证据不足则标明不确定。
- BLUF：结论先行，再给原因、命令与验证。
- 版本、第三方行为、路径、配置、API、报错：先工具 / 源码 / 日志 / 官方文档核实。
- 复杂任务先短计划；关键假设与歧义先说清；破坏性 / 付费 / 生产变更先确认。
- 授权内做到底，不逐步重问；点名工具失败则报告并问，不擅自换。
- 执行类以「交付并复核」为完成；问答类答清并标明已核实 / 推测。

## 修改与验证

- Occam / YAGNI：需求边界内最小实现；复用现有代码与依赖；保护用户未提交改动。
- 推测性竞态 /「理论上更安全」的复杂度：先陈述失败模式、概率与代价，同意后再做。
- 边界校验一次（parse, don't validate）；内部信任类型；只捕能处理的错，不静默吞。
- 不预先抽只用一次的 helper（Rule of Three）。
- 改前说明文件与意图；批量改要可审查、可回滚。
- 验证必须，新增测试非默认：跑覆盖本次改动的最小现有检查，默认不全量。
- 新测试须对应具体、现实的回归；禁止事后补 unit tests 凑数。
- E2E-first：从真实入口验可观察行为；高层已覆盖则不加重复低层测；留可复现 artifact（报告 / 截图 / 日志 / 命令）。隔离测仅当 E2E 不合理时，且先列失败模式。
- 验收证据用 `git status` / `git diff`，不用哈希「证明未改」。
- 委派不得扩大测试范围或绕过上述策略；只声称有证据的结论。
- 提交信息不加 `Co-Authored-By` 等署名。
- Docs-as-code 优先：除 `AGENTS.md`、`README.md`、必要 ADR、对外契约原文、`SECURITY`、极薄运维入口外，默认不扩文档；抉择不得只靠叙事文档。
- Worktree 不遗留：完成则 `remove` + 删分支；未合入先 commit 并打 `archive/<名>` tag。编排方收尾派生 worktree；须保留的在最终回复点名原因。

## 进程与资源

- Who starts owns teardown：后台测 / 服务 / 监听记录用途、cwd、PID/pgid；交付前清零本轮孤儿进程（按 PID，不按宽泛名字）；保留须用户明确或任务仍依赖，并写明停止方式。

## 渐进式发现

- 约束：全局 → 仓根 → 最近目录；更具体者覆盖其范围；冲突指出来源。
- 匹配 skill 则完整读 `SKILL.md`；专项流程不进本文件。
- 架构 / 命令从最近项目规则读；文档与代码冲突以代码为准，并指出不一致。
- 角色差异只在角色配置里补，不复制本文件。

## Shell 与工具输出

- 大文件用内置 `read`（offset/limit）或落盘再切片；先 `rg` 定位，单次约 ≤200 行；勿整文件 `cat`。
- 已自动加载的 AGENTS / 项目规则不要再 `read`；Computer Use 只回结论 / 精简 AX，不把整图塞进父会话。

## 沟通

- 短、直接、高密度；命令 / 路径 / 错误 / API 名保留原文。
- 长任务按阶段报实际结果；失败说卡点与下一步。
